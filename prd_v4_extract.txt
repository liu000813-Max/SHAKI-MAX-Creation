[P0][Normal] SHAKI AI Matching Engine 技术PRD
[P1][Normal] SHAKI AI Matching Engine — Technical PRD
[P2][Normal] 500 SKU → 80 Candidates → 20 High-Match → 5 Curated Recommendations | 中英文双语
[P3][Normal] 目标 / Goal: 把“客户研究 + 产品知识 + 六维评分 + 商业机会”变成稳定、可解释、可测试的推荐流水线，而不是一次性的LLM自由生成。 / Convert client research, product knowledge, six-dimension scoring and opportunity detection into a deterministic, explainable ranking pipeline instead of free-form LLM guessing.
[P4][Heading 1] 1. 产品目标 / Product Goal
[P5][List Bullet] 输入一个客户：主营品类 + 官网 + 社媒 + 市场/客户类型。 — Input: main categories + website + social URLs + market / customer type.
[P6][List Bullet] 从500个SKU开始，经过硬过滤、语义召回、业务评分、机会评分、多样性重排，最终输出5个推荐。 — Start from 500 SKUs and end with 5 recommendations using hard filters, semantic retrieval, business scoring, opportunity scoring and diversification.
[P7][List Bullet] 每个推荐必须输出：Fit Score、Potential Score、Confidence、Evidence、Reason。 — Every recommendation must output Fit Score, Potential Score, Confidence, Evidence and Reason.
[P8][Heading 1] 2. 系统边界与输入 / System Boundary & Inputs
[P9][Heading 1] 3. 推荐流水线 / Recommendation Pipeline
[P10][Normal] 推荐引擎固定为以下七层： / The engine is fixed into seven layers:
[P11][Heading 1] 4. 第1层：硬过滤 / Layer 1 — Hard Filters
[P12][Normal] 特殊规则 / Special rule: 如果客户明确要“水剂”，则Water-Based优先进入候选池；但若业务目标是“丰富设备产品线”，水剂只作为Cross-Sell候选而非主推。 / Explicit client intent overrides generic popularity.
[P13][Heading 1] 5. 第2层：语义召回 / Layer 2 — Semantic Recall
[P14][Normal] 对通过硬过滤的SKU计算向量相似度，召回Top 80。 / Compute semantic similarity over eligible SKUs and recall Top 80.
[P15][Normal] 推荐向量建议：pgvector 或等价向量数据库；同时保留关键词/规则召回，避免纯语义召回遗漏明确品类。 / Use pgvector or equivalent, combined with keyword/rule retrieval so explicit category intent is not lost.
[P16][Heading 1] 6. 第3层：六维 Client Fit Score / Layer 3 — Six-Dimension Client Fit Score
[P17][Heading 2] 6.1 Normalized score formula / 标准化公式
[P18][Normal] 每个维度先得到0–100的子分，再做加权：
[P19][Normal] Fit = 0.20·Category + 0.20·Audience + 0.15·Brand + 0.15·Price + 0.15·Portfolio + 0.15·Market
[P20][Normal] 所有分数四舍五入到整数；保存原始小数分在日志中用于调参与回溯。 / Round display to integer; preserve raw decimals in logs.
[P21][Heading 1] 7. 六维子评分规则 / Six-Dimension Scoring Rules
[P22][Heading 2] Category Fit / 品类适配
[P23][List Bullet] 100：Primary category直接命中客户核心品类
[P24][List Bullet] 85：Secondary category高度相关
[P25][List Bullet] 70：功能相关但品类不完全相同
[P26][List Bullet] 40：仅场景相关
[P27][List Bullet] 0：客户明确排除
[P28][Heading 2] Audience Fit / 用户适配
[P29][List Bullet] 100：性别 + 年龄 + 场景三项高度匹配
[P30][List Bullet] 90：性别与场景匹配，年龄未知
[P31][List Bullet] 75：人群相邻
[P32][List Bullet] 50：需要明显教育
[P33][List Bullet] 0：明显冲突
[P34][Heading 2] Brand Fit / 品牌风格
[P35][List Bullet] 100：设计风格、包装、价格定位高度一致
[P36][List Bullet] 90：两项高度一致，一项中等
[P37][List Bullet] 75：风格相容但品牌层级不完全一致
[P38][List Bullet] 50：视觉/品牌差异明显
[P39][List Bullet] 0：品牌调性冲突
[P40][Heading 2] Price Fit / 价格带
[P41][List Bullet] 100：产品落在客户历史价格走廊中部
[P42][List Bullet] 90：接近走廊边界
[P43][List Bullet] 75：略高/略低但有商业逻辑
[P44][List Bullet] 50：明显跨档
[P45][List Bullet] 0：不符合采购逻辑
[P46][Heading 2] Portfolio Fit / 产品线
[P47][List Bullet] 100：补足明确空缺且不重复
[P48][List Bullet] 90：补足近邻空缺
[P49][List Bullet] 75：存在部分重叠但仍有差异
[P50][List Bullet] 50：高度重复
[P51][List Bullet] 0：完全重复且无新增价值
[P52][Heading 2] Market Fit / 市场
[P53][List Bullet] 100：目标市场优先 + 合规信息完整 + 需求高
[P54][List Bullet] 90：市场匹配但数据不完整
[P55][List Bullet] 75：市场可进入但机会一般
[P56][List Bullet] 50：市场证据弱
[P57][List Bullet] 0：明确不可进入
[P58][Heading 1] 8. 第4层：Potential Score / Layer 4 — Potential Score
[P59][Normal] Potential = 0.25·Gap + 0.25·MarketOpp + 0.20·Diff + 0.15·PriceExp + 0.15·Strategic
[P60][Heading 1] 9. 第5层：最终推荐分 / Layer 5 — Final Recommendation Score
[P61][Normal] Final Recommendation Score用于对20个高匹配候选继续排序：
[P62][Normal] Final = 0.40·Fit + 0.20·ProductIntelligence + 0.15·MarketOpportunity + 0.10·PortfolioGap + 0.10·SalesPerformance + 0.05·StrategicValue
[P63][List Bullet] 新品没有Sales Performance时，不罚分；改用Design Value + Differentiation + Market Opportunity + Brand Value的冷启动代理分。 — For new products with no sales history, do not penalize. Use a cold-start proxy instead.
[P64][Heading 1] 10. 第6层：多样性重排 / Layer 6 — Diversity Rerank
[P65][Normal] 禁止Top 5全部是同一品类或同一视觉风格。 / Do not allow all Top 5 to collapse into one category or one visual style.
[P66][Heading 1] 11. 第7层：最终5款策展逻辑 / Layer 7 — Final Top 5 Curation
[P67][Normal] 默认组合结构：
[P68][Normal] 若某角色没有合格SKU，回退到Final Score最高且满足最小Fit阈值的候选。 / If a role has no qualified SKU, fall back to the highest-ranked candidate that satisfies minimum Fit thresholds.
[P69][Heading 1] 12. 置信度 Confidence / Confidence Model
[P70][Heading 1] 13. 证据系统 Evidence / Evidence System
[P71][Normal] 每条推荐至少保留2类证据，优先顺序：Client Website → Client Product Portfolio → Social → Market Research → Internal Product Master。
[P72][Heading 1] 14. Prompt Architecture / Prompt Architecture
[P73][Normal] Website Research Agent / Extract brand, category, price, audience, product portfolio and factual evidence.
[P74][Normal] Social Research Agent / Extract content themes, style, audience and engagement topics from accessible public profiles.
[P75][Normal] Customer Profiling Agent / Convert research into structured Client Intelligence with facts / inference / unknown separation.
[P76][Normal] Product Understanding Agent / Convert each SKU into Product DNA from master data + approved AI tags.
[P77][Normal] Product Matching Agent / Retrieve and rank candidates using client-product similarity and hard constraints.
[P78][Normal] Scoring Agent / Compute six Client Fit dimensions and Potential Score using fixed formulas.
[P79][Normal] Opportunity Agent / Identify category gaps, price gaps, premium opportunities and cross-sell opportunities.
[P80][Normal] Recommendation Agent / Create reasons, recommendation type, confidence and evidence.
[P81][Normal] Proposal Agent / Generate client-ready bilingual proposal copy without exposing internal scores.
[P82][Normal] Sales Assistant Agent / Answer business-user questions using current client + product context.
[P83][Heading 1] 15. Core Prompt / Core Prompt
[P84][Normal] You are SHAKI Product Matching Agent.
[P85][Normal] Use only verified Product Master fields for product facts.
[P86][Normal] Use client research evidence for client facts.
[P87][Normal] Separate observed facts from inferences and unknowns.
[P88][Normal] Never invent product parameters, MOQ, price, certification, sales or customer demand.
[P89][Normal] Apply hard filters before ranking.
[P90][Normal] Compute six Client Fit dimensions using the fixed weights.
[P91][Normal] Compute Potential Score separately from Fit Score.
[P92][Normal] Prefer complementarity over duplication.
[P93][Normal] Output structured JSON only.

[P139][Heading 1] 18. 可测试Acceptance Criteria / Acceptance Criteria
[P140][List Bullet] 500 valid SKUs → hard filters are deterministic and reproducible.
[P141][List Bullet] 80 recalled candidates are traceable to retrieval scores.
[P142][List Bullet] Every Fit Score can be recomputed from stored six-dimension subscores.
[P143][List Bullet] Potential Score never overwrites Fit Score.
[P144][List Bullet] Final Top 5 contains no more than 2 of the same secondary category unless explicitly justified.
[P145][List Bullet] Every recommendation reason references at least one client fact and one product fact.
[P146][List Bullet] AI never invents unverified commercial fields.
[P147][List Bullet] Chinese/English outputs remain semantically equivalent.
[P148][List Bullet] New SKU with no sales history remains eligible if Data Completeness and Fit thresholds are met.
